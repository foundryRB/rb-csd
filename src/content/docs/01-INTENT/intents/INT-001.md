```yaml
INT-001:
  version: 1.0.0

  test:
    scope: unit

    type: invariant
  criticality: critical
  domain: security
```

---

## 1. Rationale

Session isolation is fundamental to multi-tenant security. If session data can leak between users, an attacker could:

- Access another user's personal data
- Perform actions as another user
- Escalate privileges

This invariant must hold regardless of:

- System load
- Session storage backend
- Authentication method
- User role or permissions

---

## 2. Test Specification

### 2.1 Scope: Unit

**Component**: `SessionService`

**Test Type**: Invariant (must ALWAYS be true)

### 2.2 Test Binding

The attesting test carries the claim's marker; the test body proves the statement (cross-user access rejected, isolation holds regardless of user role, ideally property-based):

```typescript
intent('INT-001', 'session data never crosses user boundaries', () => {
    /* create sessions for two users; assert cross-user access is rejected */
});
```

---

## 3. Examples

### 3.1 Pass Cases

| Scenario | Expected Result |
|----------|-----------------|
| User A requests User A's session | Returns session data |
| User A requests User B's session | Throws SecurityException |
| Admin requests any session with admin override | Returns session data (if authorized) |
| Session not found | Throws SessionNotFoundException |

### 3.2 Fail Cases

| Scenario | Why It Fails |
|----------|--------------|
| User A receives User B's session data | Data crossed user boundary |
| Session ID collision returns wrong data | Implementation bug |
| Cache returns stale session for wrong user | Cache key issue |
